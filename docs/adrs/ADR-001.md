# Título: ADR-001 - Elección del Motor de Base de Datos Principal

**Estado:** Aceptado
**Fecha:** 2026-06-17
**Decisores:** Facundo Balmaceda
**Relacionado:** Issue #19

## Contexto
- **Qué problema se está resolviendo:** Se debe determinar el motor de base de datos a utilizar para el almacenamiento persistente del sistema de gestión de eventos.
- **Qué restricciones aplican:** Se requieren transacciones ACID para asegurar la integridad de las reservas de entradas y los pagos. Se necesita un esquema bien definido y estable.
- **Qué datos de proyecto sustentan la decisión:** El modelo de negocio requiere cruzar datos (joins) constantemente entre Usuarios, Eventos y Reservas.

## Decisión
**Qué se decide exactamente:**
- Se va a utilizar MySQL (versión 8.0) como motor de base de datos relacional principal del proyecto.
- **Alcance:** Cubre toda la persistencia de datos transaccionales y entidades del dominio central. No cubre almacenamiento de archivos estáticos (imágenes de eventos).

## Alternativas consideradas
- **Opción A: MongoDB (NoSQL).** Pros: Esquema flexible, alta velocidad de escritura. Contras: Falta de joins nativos, consistencia eventual que podría generar sobreventas de entradas.
- **Opción B: PostgreSQL.** Pros: Excelente motor relacional. Contras: El equipo tiene mayor fluidez y experiencia técnica configurando y manteniendo entornos en MySQL.
- **Opción C: MySQL (Seleccionada).** Pros: Transacciones ACID, madurez, excelente soporte en Node.js, cumple con los requisitos del esquema.

## Consecuencias
- **Beneficios esperados:** Integridad referencial fuerte, consistencia total en las reservas de eventos.
- **Costos o riesgos que se aceptan:** Las migraciones de esquema (schema migrations) pueden ser costosas a futuro. La escala es principalmente vertical en esta etapa inicial.
- **Impacto en operación y equipo:** El equipo debe mantener actualizados los scripts de migración.

## Plan de implementación
- **Pasos mínimos para ejecutarla:** Configurar el servicio `db` en el `docker-compose.yml` utilizando la imagen `mysql:8.0`. Establecer las variables de entorno de conexión.

## Dependencias
- Driver de conexión para Node.js (ej. `mysql2`).

## Métrica de éxito
- Tiempos de respuesta de queries complejas con joins dentro de los umbrales aceptables (< 200ms).

## Triggers de revisión
- **Qué condiciones obligan a reabrir esta ADR:** Crecimiento exponencial de la base de datos que requiera estrategias de Sharding o cuellos de botella severos en las lecturas.
