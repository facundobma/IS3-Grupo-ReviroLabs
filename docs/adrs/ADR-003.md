# Título: ADR-003 - Elección de Lenguaje y Framework para Backend

**Estado:** Aceptado
**Fecha:** 2026-06-17
**Decisores:** Nabil Chattich
**Relacionado:** Issue #23

## Contexto
- **Qué problema se está resolviendo:** Se debe seleccionar el lenguaje de programación y el framework principal para la construcción de la API REST del backend[cite: 2].
- **Qué restricciones aplican:** El equipo cuenta con un tiempo de desarrollo limitado, por lo que se requiere una tecnología con una curva de aprendizaje baja y amplia disponibilidad de librerías.
- **Qué datos de proyecto sustentan la decisión:** El sistema de gestión de eventos tendrá alta concurrencia de lectura, lo que requiere un entorno capaz de manejar múltiples peticiones asíncronas de manera eficiente.

## Decisión
**Qué se decide exactamente:**
- Se utilizará Node.js como entorno de ejecución y Express.js como framework web minimalista.
- **Alcance:** Cubre la capa de controladores, rutas y lógica de negocio principal del sistema de ReviroLabs. 

## Alternativas consideradas
- **Opción A: Python / Django.** Pros: Excelente para validaciones rápidas, robusto. Contras: Mayor consumo de recursos para operaciones asíncronas y reglas muy estrictas que limitan la flexibilidad inicial.
- **Opción B: Java / Spring Boot.** Pros: Tipado fuerte, excelente rendimiento a gran escala. Contras: Verbosidad extrema y curva de configuración inicial muy lenta para el MVP.
- **Opción C: Node.js / Express (Seleccionada).** Pros: Ecosistema NPM gigante, I/O no bloqueante ideal para peticiones concurrentes, permite usar el mismo lenguaje (JavaScript) en el frontend y backend.

## Consecuencias
- **Beneficios esperados:** Rapidez en el desarrollo del MVP, facilidad para implementar WebSockets a futuro, amplia comunidad de soporte.
- **Costos o riesgos que se aceptan:** Riesgo de "callback hell" o código desordenado si no se mantiene una arquitectura estricta; es un sistema de un solo hilo, lo que dificulta tareas pesadas de CPU.
- **Impacto en operación y equipo:** El equipo deberá estandarizar el uso de Promesas (async/await) para mantener la legibilidad.

## Plan de implementación
- **Pasos mínimos para ejecutarla:** Inicializar el proyecto con `npm init`, instalar la dependencia `express`, y crear el archivo de entrada `app.js` configurado en el contenedor Docker.

## Dependencias
- Entorno de ejecución Node.js y gestor de paquetes NPM.

## Métrica de éxito
- Lograr levantar el servidor base y el primer endpoint de prueba operativo en menos de un sprint.

## Triggers de revisión
- **Qué condiciones obligan a reabrir esta ADR:** Si el producto evoluciona y requiere procesamiento intensivo de datos (ej. manipulación pesada de imágenes o video), Node.js podría convertirse en un cuello de botella.
